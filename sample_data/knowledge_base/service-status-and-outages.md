# Checking CloudDesk service availability

When a feature is unavailable, check the approved service-status source for an active incident affecting that component. Ask which workspace and operation are affected, when the issue began, and whether it is intermittent or continuous.

## During a confirmed incident

Use only the incident details that have been published for support. Explain the known impact and any approved next step without speculating about root cause or restoration time. Do not ask the customer to repeat risky actions that could cause data loss or duplicate transactions.

## If no incident is listed

Collect the affected service, approximate time, request or correlation ID, and a safe description of the error. Check whether a local browser, network, or workspace-specific setting could explain the behavior. If multiple users or customers show the same symptoms, report the pattern to the on-call support team for investigation.
