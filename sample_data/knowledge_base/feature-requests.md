# Submitting product feedback and feature requests

Acknowledge the request and capture the problem the customer is trying to solve, the affected workflow, and the impact on their team. Distinguish a missing feature from a defect or a configuration issue so it can be routed correctly.

## Record actionable context

Ask for an example of the current workflow and the desired outcome. Avoid collecting confidential files or information about other customers. Include relevant plan or workspace context only when it is needed to understand the request.

## Set expectations

Submit the request through the approved feedback channel. Do not promise that a feature will be built or provide an unconfirmed release date. Share only public roadmap information that has been approved for customers; report an existing product failure through the incident or bug process instead.
