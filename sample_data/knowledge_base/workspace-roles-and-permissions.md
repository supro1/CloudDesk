# Workspace roles and access permissions

When a user cannot see an action or resource, confirm the workspace and the user's current role. Access may depend on both workspace membership and the permission required for the specific action.

## Verify membership and role

Ask a workspace administrator to check that the user is an active member and has the intended role. Compare the missing action with the current role's documented permissions. Do not grant administrator access as a troubleshooting shortcut.

## Make a permission change

Only an authorized workspace administrator should approve role or membership changes. Confirm the intended user and minimum required access before changing permissions. If access changed unexpectedly or the administrator did not make the change, treat it as a potential security incident and escalate.
