# CloudDesk Support — API Contract

This is the intended REST contract for the product described in
[`CLAUDE.md`](../CLAUDE.md). It documents target behavior; it does not assert
that these routes currently exist. Keep this file, backend Pydantic schemas,
and `frontend/lib/types.ts` synchronized when implementing or changing routes.

## Conventions

- Base path: `/api/v1`, except health probes.
- Authentication: `Authorization: Bearer <JWT>` for protected routes.
- Every response includes `X-Request-ID`; requests may supply one to correlate
  logs and events.
- JSON request and response bodies use `snake_case`.
- Errors use `{"detail": "<message>"}`.
- Requests are limited per client IP in fixed 60-second windows using Redis.
  Exceeding `RATE_LIMIT_PER_MINUTE` returns `429` with a `Retry-After` header;
  an unavailable rate-limit store returns `503`.
- Authenticated routes enforce the role table below server-side. The UI's
  disabled controls are not an authorization boundary.
- Pagination uses `limit` and `offset` where a list endpoint supports them.
- Timestamps are ISO 8601 UTC strings. IDs are UUID strings unless otherwise
  noted.

### Roles

| Role | Read | Run workflow/reply/escalate | Approve/reject | Admin operations |
|---|---:|---:|---:|---:|
| `viewer` | Yes | No | No | No |
| `agent` | Yes | Yes | Yes | No |
| `admin` | Yes | Yes | Yes | Yes |

### Shared enums

- `category`: `login_issue`, `billing`, `api_failure`,
  `workspace_permissions`, `storage_quota`, `integration`,
  `feature_request`, `account`, `security`, `other`.
- `severity`: `low`, `medium`, `high`, `critical`.
- `channel`: `email`, `chat`, `web`, `api`.
- `ticket_status`: `new`, `in_progress`, `waiting_on_customer`,
  `waiting_on_approval`, `escalated`, `resolved`, `closed`.
- `approval_status`: `pending`, `approved`, `rejected`.

## Health

These routes are unprefixed and require no user JWT.

| Method and path | Purpose | Response |
|---|---|---|
| `GET /health` | General health response. | `200` with service status. |
| `GET /health/live` | Liveness probe; no dependency I/O. | `200` when process is alive. |
| `GET /health/ready` | Readiness check for database, Redis, vector store, and LLM provider. | `200` when ready; non-2xx when a required dependency is unavailable. |

## Authentication

| Method and path | Role | Purpose |
|---|---|---|
| `POST /api/v1/auth/login` | Public/demo | Authenticate a demo user and return a JWT and profile. |
| `GET /api/v1/auth/me` | Any authenticated role | Return the current profile and role. |

Login response shape:

```json
{
  "access_token": "<JWT>",
  "token_type": "bearer",
  "expires_in": 28800,
  "user": {
    "id": "<uuid>",
    "email": "sam.agent@clouddesk.demo",
    "role": "agent",
    "display_name": "Sam Rivera"
  }
}
```

Demo identities are `admin@clouddesk.demo`, `sam.agent@clouddesk.demo`, and
`vic.viewer@clouddesk.demo`. Demo tokens expire in eight hours. Production
authentication must validate JWTs using the configured signing secret; do not
infer authorization from client-supplied role fields.

Login request:

```json
{
  "email": "sam.agent@clouddesk.demo"
}
```

The login route is available only when `DEMO_MODE=true` and a JWT signing secret
is configured. It accepts only active seeded demo profiles; unknown identities
receive `401`, and disabled demo login receives `403`. `/me` requires a valid
bearer token and returns the active profile associated with its subject. Demo
login intentionally has no password verification and must remain disabled
outside local/demo environments.

## Tickets

Ticket records use UUIDs for `id`; `ticket_number` is the human-readable,
server-assigned identifier. Ticket fields:

| Field | Type | Notes |
|---|---|---|
| `id` | string (UUID) | Stable resource identifier. |
| `ticket_number` | string | Unique identifier such as `CD-1001`; generated by the server. |
| `customer_id` | string (UUID) | Existing customer associated with the ticket. |
| `subject` | string | Required, 1–300 characters. |
| `channel` | enum | `email`, `chat`, `web`, or `api`. |
| `status` | enum | `new`, `in_progress`, `waiting_on_customer`, `waiting_on_approval`, `escalated`, `resolved`, or `closed`. |
| `category` | enum or `null` | One of the shared categories; may be unclassified initially. |
| `severity` | enum or `null` | `low`, `medium`, `high`, `critical`, or `null` until assessed. |
| `severity_reason` | string or `null` | Explanation for the assigned severity. |
| `summary` | string or `null` | Concise ticket summary; may be absent before classification. |
| `external_id` | string or `null` | Optional originating-system ID; unique per channel when supplied. |
| `created_at`, `updated_at` | ISO 8601 UTC string | Server-managed timestamps. |

| Method and path | Role | Purpose |
|---|---|---|
| `POST /api/v1/tickets` | `agent`+ | Create a ticket and its initial customer message. |
| `GET /api/v1/tickets` | Any authenticated role | List tickets with pagination and filters. |
| `GET /api/v1/tickets/{ticket_id}` | Any authenticated role | Return the ticket, messages, customer summary, and available workflow/approval summary. |
| `PATCH /api/v1/tickets/{ticket_id}` | `agent`+ | Update supported agent-editable fields. |
| `POST /api/v1/tickets/{ticket_id}/run` | `agent`+ | Start workflow; returns `202` and a workflow ID. |
| `GET /api/v1/tickets/{ticket_id}/workflow` | Any authenticated role | Return latest workflow status and current state summary. |
| `GET /api/v1/tickets/{ticket_id}/events` | Any authenticated role | Return inspectable workflow events without prompts/secrets. |
| `POST /api/v1/tickets/{ticket_id}/reply` | `agent`+ | Validate and record/send a customer reply through the mock integration. |
| `POST /api/v1/tickets/{ticket_id}/request-info` | `agent`+ | Record a request for more customer information. |
| `POST /api/v1/tickets/{ticket_id}/escalate` | `agent`+ | Escalate the ticket with a reason and named team. |

### Create ticket

`POST /api/v1/tickets` accepts:

```json
{
  "subject": "Uploads fail",
  "body": "Customer-provided message",
  "customer_id": "<customer-uuid>",
  "channel": "web",
  "external_id": null
}
```

`subject`, `body`, `customer_id`, and `channel` are required. `body` must be a
non-empty string. `external_id` is optional and nullable. The server generates
`id` and `ticket_number`, sets `status` to `new`, and records `body` as the
first message with `sender_type: "customer"` and `is_internal: false`.
Classification and severity fields are initially `null` unless set by a
subsequent workflow. Clients cannot set server-managed IDs, timestamps, status,
classification, severity, or summary during creation.

Returns `201 Created` with the created ticket and its initial message. A
nonexistent `customer_id` returns `404`; an already-used `(channel,
external_id)` returns `409`. Invalid fields or enum values return `422`.

### List and detail

`GET /api/v1/tickets` accepts `limit` (default `50`, range `1–100`) and
`offset` (default `0`, non-negative), plus optional exact-match filters:
`status`, `category`, `severity`, `channel`, and `customer_id`. Results are
ordered newest first, with a stable ID tie-breaker.

```json
{
  "items": [
    {
      "id": "<uuid>",
      "ticket_number": "CD-1001",
      "subject": "SSO login fails for whole team",
      "customer_id": "<uuid>",
      "channel": "email",
      "status": "new",
      "category": "login_issue",
      "severity": "high",
      "severity_reason": "The whole team is unable to sign in.",
      "summary": null,
      "external_id": "mail-1001",
      "created_at": "2026-01-01T00:00:00Z",
      "updated_at": "2026-01-01T00:00:00Z"
    }
  ],
  "total": 1,
  "limit": 50,
  "offset": 0
}
```

`GET /api/v1/tickets/{ticket_id}` returns the ticket fields above, an ordered
`messages` array, a customer summary (`id`, `name`, `email`, and nullable
`company_name`), and workflow/approval summaries only when those resources
exist. Each message contains `id`, `ticket_id`, `sender_type`, nullable
`sender_name`, `body`, `is_internal`, and `created_at`. Messages are ordered
oldest first. `ticket_id` must be a ticket UUID; unknown IDs return `404`.

### Update ticket

`PATCH /api/v1/tickets/{ticket_id}` accepts a non-empty JSON object containing
only supported agent-editable fields: `status`, `category`, `severity`,
`severity_reason`, and `summary`. Enum values must match the shared enums.
Fields not provided remain unchanged; nullable classification/summary fields
may be explicitly cleared with `null`. IDs, customer, channel, external ID,
messages, and timestamps are not editable through this endpoint. Returns the
updated ticket; unknown IDs return `404` and invalid or unsupported fields
return `422`.

Workflow start response:

```json
{
  "workflow_id": "<uuid>",
  "status": "queued"
}
```

The run endpoint responds with `409 Conflict` if the ticket is already
`waiting_on_approval`. Resuming a run that is not paused also returns `409`.
Validation errors return `422`, missing resources return `404`, and insufficient
role returns `403`.

## Approvals

Approval object:

```json
{
  "id": "<uuid>",
  "ticket_id": "<uuid>",
  "workflow_id": "<uuid>",
  "action": "create_refund_request",
  "summary": "Request a billing adjustment for unused seats.",
  "status": "pending",
  "requested_at": "2026-01-01T00:00:00Z",
  "decided_at": null,
  "decided_by": null
}
```

| Method and path | Role | Purpose |
|---|---|---|
| `GET /api/v1/approvals` | `agent`+ | List approval requests visible to the agent. |
| `POST /api/v1/approvals/{approval_id}/approve` | `agent`+ | Record approval and resume the paused workflow. |
| `POST /api/v1/approvals/{approval_id}/reject` | `agent`+ | Record rejection and route through the configured safe path. |

Approve/reject requests may include a `reason`. A decision is durable and
auditable; clients cannot directly execute the action by sending an `approved`
flag to a tool endpoint.

## Customers

Customer fields are `id` (UUID), `name`, `email`, nullable `company_name`,
`created_at`, and `updated_at`. This API is read-only; customer creation and
mutation are not exposed.

| Method and path | Role | Purpose |
|---|---|---|
| `GET /api/v1/customers` | Any authenticated role | List customers with pagination and optional filters. |
| `GET /api/v1/customers/{customer_id}` | Any authenticated role | Return one customer with subscriptions, workspaces, and recent ticket history. |

`GET /api/v1/customers` accepts `limit` (default `50`, range `1–100`),
`offset` (default `0`, non-negative), and optional exact-match `email` and
`company_name` filters. It returns the standard page shape:
`{"items": [], "total": 0, "limit": 50, "offset": 0}`. Results are ordered
newest first with a stable ID tie-breaker.

`GET /api/v1/customers/{customer_id}` returns:

```json
{
  "customer": {
    "id": "<uuid>",
    "name": "Maya Patel",
    "email": "maya@example.test",
    "company_name": "Northstar Health",
    "created_at": "2026-01-01T00:00:00Z",
    "updated_at": "2026-01-01T00:00:00Z"
  },
  "subscriptions": [],
  "workspaces": [],
  "recent_tickets": []
}
```

Each subscription includes `id`, `plan_name`, `status`, `seat_count`,
`seats_used`, `storage_limit_bytes`, `storage_used_bytes`,
`current_period_start`, and `current_period_end`. Each workspace includes
`id`, `name`, `slug`, `settings`, and `is_active`. `recent_tickets` contains
the customer's latest 20 ticket summaries using the ticket fields above,
without messages. Use `GET /api/v1/tickets?customer_id=...` for paginated
history. A nonexistent customer ID returns `404`.

Customer responses must not include secrets or data belonging to other
customers. Do not expose customer-memory notes in these endpoints.

## Knowledge

| Method and path | Role | Purpose |
|---|---|---|
| `GET /api/v1/knowledge` | Any authenticated role | List available knowledge articles. |
| `GET /api/v1/knowledge/{article_id}` | Any authenticated role | Return an article's permitted content and metadata. |
| `POST /api/v1/knowledge/search` | Any authenticated role | Search using `query`, optional `category`, `mode`, and `top_k`. |
| `POST /api/v1/knowledge/reindex` | `admin` | Recreate/reindex the configured knowledge collection. |

Evidence objects:

```json
{
  "id": "<chunk-id>",
  "title": "Account recovery",
  "source": "kb://account-recovery#reset-mfa",
  "snippet": "Relevant cited excerpt.",
  "score": 0.87,
  "url": "/knowledge/<article-id>",
  "article_id": "<article-id>"
}
```

Search modes are `hybrid`, `semantic`, and `keyword`; the default is `hybrid`.
Knowledge is the only source for customer-facing policy claims, and responses
must retain article citations.

## Agents and workflow metadata

| Method and path | Role | Purpose |
|---|---|---|
| `GET /api/v1/agents` | Any authenticated role | Return workflow node and edge metadata used by the console. |

Workflow events may include `node_started`, `node_completed`, `tool_called`,

## MCP tools

| Method and path | Role | Purpose |
|---|---|---|
| `GET /api/v1/mcp/tools` | Any authenticated role | List available MCP tool metadata. |

Tool execution remains behind the same registry and policy used by the workflow.

or audit controls.

## Error behavior

| Status | Meaning |
|---:|---|
| `400` | Invalid state transition or malformed operation. |
| `401` | Missing, invalid, or expired authentication. |
| `403` | Authenticated user lacks the required role. |
| `404` | Ticket, customer, approval, escalation, or article does not exist. |
| `409` | Conflicting workflow/approval state; includes the documented already-waiting or not-paused cases. |
| `422` | Request validation failed. |
| `429` | Rate limit exceeded. |
| `5xx` | Unexpected server/dependency failure; do not return success-shaped fallback data. |

Error responses use `{"detail": "..."}` and include the response `X-Request-ID`.
Do not include secrets, raw prompts, or another customer's data in error details.
